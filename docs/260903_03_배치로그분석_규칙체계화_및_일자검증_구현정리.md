## 1. 추진 배경 및 사용자 요구사항

기존 일간 배치 로그 분석 시스템의 운영 편의성 및 검증 신뢰도를 높이기 위해 다음과 같은 요구사항을 수렴하여 기능을 고도화하였습니다.

1. **규칙 번호(`ruleNo`) 체계화**:
   - JSON 정책 내 각 JOB에 등록된 검증 규칙들을 고유 순번(`01`, `02`, `03`...)으로 식별 및 관리 (`[01] 배치파일점검`부터 시작).
2. **배치 실행시간/주기 기반 로그 일자 정상 취합 점검 (`LogDateChecker`)**:
   - 일간 배치의 경우 `09:05` 이전 실행 배치는 **당일(CURRENT_DAY)** 일자 로그, `09:05` 이후 실행 배치는 **전일(PREVIOUS_DAY)** 일자 로그가 정상 수집되었는지 자동 검증.
   - 월간 배치의 경우 매월 1일 실행되어 매월 2일 생성되는 로그 규칙 지원 (`scheduleType: "MONTHLY"`, `monthlyLogDay: 2`).
3. **정책 JSON 데이터 간소화 및 환경설정 일관화**:
   - JSON 정책에는 복잡한 구분값 대신 `scheduleTime` (실행시간)만 심플하게 관리.
   - 당일/전일 분기 기준 시각(`log.cutoff.time=09:05`)을 `application.properties` 환경설정으로 일관 관리하여 시간으로 구분값 자동 계산.
4. **시간 무관 전체 로그 처리 옵션 지원**:
   - 배치 일자 검증을 건너뛰고 작업 폴더 내 모든 로그를 일괄 검증하는 CLI 옵션(`--skipDateCheck` / `--allLogs`) 및 설정(`log.date.check.enabled=false`) 지원.
5. **18번째 월간배치(`smpmJob206`) 정책 추가 및 3대 비즈니스 검증**:
   - `206_협회코드및보험사코드수집` (`_11294_`, `00:45 [2일 / 월]`)
   - `HTTP/1.1 200` 거래성공 확인, `prodList.size 40` 이전데이터 정리 건수, `TB_SMPM1002.insIntgCode 151건` 실행 확인.
6. **테스트 영속성을 위한 로그 경량화 (`LogSlimmer`) 유틸리티 구축**:
   - 대용량 실로그(수백 MB)에서 핵심 검증 라인만 보존하여 99.8% 경량화(총 900KB)하고 Git에 안전하게 영속화.
7. **리포트(Console & Markdown) 서식 고도화**:
   - **`[01] 배치파일점검`**: 첫 번째 검증 항목으로 로그 일시 추출 및 수집 상태(`정상파일수집`)를 간결하게 표시.
   - **`JOB ID` 열**: 줄바꿈으로 배치시간 및 주기 정보(`03:05 [당일 / 일]`, `11:00 [전일 / 일]`, `00:45 [2일 / 월]`) 표기.
8. **Gradle 래퍼 환경 개선**:
   - `gradle-wrapper.properties` 버전을 `8.9`로 현행화하고 `.gitignore`에서 래퍼 스크립트 및 jar 트래킹 예외 명시.

## 2. 시스템 아키텍처 및 설계 원칙

```
[CheckLog.main / runAnalysis]
        │
        ▼
[BatchLogAnalysisService] ─── CLI 인자(--skipDateCheck) & 작업 폴더 해석
        │
        ▼
[LogAnalyzer.checkJob] ────── 1. LogFileLocator (로그 파일 패턴 매칭)
        │
        ├──────────────────── 2. LogDateChecker (ruleNo: "01" 배치파일점검)
        │                        - 로그 첫 타임스탬프 파싱
        │                        - BaseDate 감지 (폴더명 / 로그파일 MAX 날짜)
        │                        - log.cutoff.time(09:05) 기반 당일/전일/월간 기대일자 계산
        │
        ├──────────────────── 3. HolidayChecker (비영업일 예외 점검)
        │
        └──────────────────── 4. RuleEvaluatorRegistry (ruleNo: "02"~ 규칙 평가)
                                 - DisplayRuleEvaluator (DISPLAY)
                                 - SearchRuleEvaluator (SEARCH)
                                 - StepMetricsRuleEvaluator (STEP_METRICS)
        │
        ▼
[ReportGenerator] ─────────── ConsoleReportWriter (콘솔 표 출력)
                              MarkdownReportWriter (마크다운 보고서 저장)
```

- **단일 책임 원칙 (SRP)**:
  - `LogDateChecker`: 로그 실행 일시 추출 및 스케줄 정책 기반 일자 취합 유효성 검증만 전담.
  - `CheckResult`: JOB별 메타 및 `scheduleInfo`(`03:05 [당일 / 일]`) 서식화 담당.
  - `ReportWriter`: 가독성 높은 표 형식 렌더링 전담.
  - `LogSlimmer`: 대용량 로그에서 핵심 검증 라인 추출 및 경량화 전담.
- **개방-폐쇄 원칙 (OCP)**:
  - 신규 스케줄 유형이나 평가 규칙이 추가되더라도 기존 검증 엔진의 수정 없이 독립 확장 가능.

## 4. 정책 JSON 설정 가이드

### 일간 배치 (기본)
```json
{
  "jobNo": "01",
  "jobName": "gagastJob002",
  "jobTitle": "gagastJob002 추천터치고객 통계 데이터 적립",
  "filePrefix": "01_gagastJob002_",
  "rawPattern": "_10702_",
  "scheduleTime": "03:05",
  "rules": [
    {
      "ruleNo": "02",
      "type": "DISPLAY",
      "target": "DB Insert GA Count",
      "condition": "EQUALS_0",
      "description": "DB Insert GA Count 0건 체크"
    }
  ]
}
```
- `scheduleTime`: 실행 시각 (`03:05`). `log.cutoff.time`(09:05) 이하이므로 분석 기준일 **당일** 로그로 자동 판정됩니다.
- 09:05 초과 시각(예: `11:00`, `15:30`)인 경우 분석 기준일 **전일** 로그로 자동 판정됩니다.

### 월간 배치
```json
{
  "jobNo": "18",
  "jobName": "smpmJob206",
  "jobTitle": "206_협회코드및보험사코드수집",
  "filePrefix": "18_smpmJob206_",
  "rawPattern": "_11294_",
  "scheduleTime": "00:45",
  "scheduleType": "MONTHLY",
  "monthlyLogDay": 2,
  "rules": [
    {
      "ruleNo": "02",
      "type": "SEARCH",
      "target": "HTTP/1.1 200",
      "condition": "COUNT_CHECK",
      "description": "HTTP/1.1 200 거래성공확인"
    },
    {
      "ruleNo": "03",
      "type": "DISPLAY",
      "target": "prodList.size",
      "condition": "COUNT_CHECK",
      "description": "prodList.size 이전데이터 정리 건수"
    },
    {
      "ruleNo": "04",

      "target": "TB_SMPM1002.insIntgCode",
      "condition": "EQUALS_N",
      "expectedCount": 151,
      "description": "TB_SMPM1002.insIntgCode 151건 실행 확인"
    }
  ]
}
```
- `scheduleType`: `"MONTHLY"`
- `monthlyLogDay`: `2` (매월 1일 실행되어 매월 2일 생성되는 로그 일자 자동 검증)
