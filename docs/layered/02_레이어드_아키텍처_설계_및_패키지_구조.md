## 3. 계층 간 상호작용 및 시퀀스 다이어그램 (Sequence Flow)

사용자가 CLI 명령어를 실행했을 때, 4개 계층을 거쳐 처리되는 전체 흐름입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자 (CLI)
    participant CLI as Presentation (CliRunner)
    participant AppService as Application (AnalysisService)
    participant PolicyRepo as Infrastructure (PolicyRepository)
    participant LogRepo as Infrastructure (LogFileRepository)
    participant Pipeline as Domain (AnalysisPipeline)
    participant View as Presentation (ReportView)

    User->>CLI: java -jar app.jar --logFileSrc=20260901 --skipDateCheck
    activate CLI
    CLI->>CLI: CliArgumentExtractor로 DTO 변환 (AnalysisRequestDto)
    
    CLI->>AppService: analyze(AnalysisRequestDto)
    activate AppService

    %% 1. 정책 로드
    AppService->>PolicyRepo: loadPolicies()
    activate PolicyRepo
    PolicyRepo-->>AppService: List of JobPolicy 반환
    deactivate PolicyRepo

    %% 2. 대상 폴더 및 파일 조회
    AppService->>LogRepo: findWorkFolderAndLogs(requestDto)
    activate LogRepo
    LogRepo-->>AppService: LogFolderContext 반환
    deactivate LogRepo

    %% 3. 도메인 분석 실행
    loop 각 JobPolicy별 분석
        AppService->>Pipeline: execute(jobPolicy, logFolderContext)
        activate Pipeline
        Pipeline->>Pipeline: Holiday -> FileMatch -> DateCheck -> Rule
        Pipeline-->>AppService: CheckResult
        deactivate Pipeline
    end

    AppService->>AppService: 결과 종합하여 AnalysisResponseDto 생성
    AppService-->>CLI: AnalysisResponseDto 반환
    deactivate AppService

    %% 4. 결과 출력 및 파일 저장 (Presentation)
    CLI->>View: renderConsole(AnalysisResponseDto)
    CLI->>View: renderMarkdownFile(AnalysisResponseDto)
    CLI-->>User: 콘솔 리포트 출력 및 마크다운 파일 저장 완료 알림
    deactivate CLI
```

## 4. 계층 간 데이터 전송 객체 (DTO) 설계

### 4.1 요청 DTO (`AnalysisRequestDto`)
```java
package com.batch.application.dto;

public class AnalysisRequestDto {
    private final String logFileSrc;
    private final boolean autoRename;
    private final boolean skipDateCheck;

    public AnalysisRequestDto(String logFileSrc, boolean autoRename, boolean skipDateCheck) {
        this.logFileSrc = logFileSrc;
        this.autoRename = autoRename;
        this.skipDateCheck = skipDateCheck;
    }

    public String getLogFileSrc() { return logFileSrc; }
    public boolean isAutoRename() { return autoRename; }
    public boolean isSkipDateCheck() { return skipDateCheck; }
}
```

### 4.2 응답 DTO (`AnalysisResponseDto`)
```java
package com.batch.application.dto;

import com.batch.domain.model.CheckResult;
import java.util.List;

public class AnalysisResponseDto {
    private final boolean success;
    private final String folderName;
    private final int totalJobs;
    private final int normalJobs;
    private final int errorJobs;
    private final List<CheckResult> jobResults;

    // Builder 또는 생성자 제공
    public boolean isSuccess() { return success; }
    public String getFolderName() { return folderName; }
    public int getTotalJobs() { return totalJobs; }
    public int getNormalJobs() { return normalJobs; }
    public int getErrorJobs() { return errorJobs; }
    public List<CheckResult> getJobResults() { return jobResults; }
}
```

## 5. 레이어드 아키텍처의 엄격한 의존성 규칙 (Dependency Rules)

```mermaid
flowchart TD
    Pres["Presentation"]
    App["Application"]
    Dom["Domain"]
    Infra["Infrastructure"]

    Pres -->|"허용 (요청 전달)"| App
    Pres -->|"허용 (DTO 참조)"| App
    App -->|"허용 (도메인 호출)"| Dom
    App -->|"허용 (데이터 접근)"| Infra
    Dom -.->|"허용 (인터페이스 정의)"| Infra

    Pres -.->|"금지: 계층 건너뛰기"| Dom
    Pres -.->|"금지: 계층 건너뛰기"| Infra
    Dom -.->|"금지: 상위 계층 참조"| App
    Dom -.->|"금지: 상위 계층 참조"| Pres
    Infra -.->|"금지: 상위 계층 참조"| Pres

    style Pres fill:#e3f2fd,stroke:#1565c0,stroke-width:2px,color:#0d47a1
    style App fill:#e8f5e9,stroke:#2e7d32,stroke-width:2px,color:#1b5e20
    style Dom fill:#fff3e0,stroke:#e65100,stroke-width:2px,color:#bf360c
    style Infra fill:#fce4ec,stroke:#c2185b,stroke-width:2px,color:#880e4f
```

1. **규칙 1: Presentation은 Infrastructure를 직접 호출하지 않는다.**
2. **규칙 2: Application은 비즈니스 흐름 제어에 집중하며 뷰(View)를 조작하지 않는다.**
3. **규칙 3: Domain은 가장 독립적이어야 한다.**
4. **규칙 4: Spring IoC를 100% 활용한다.**
